# 图书馆界面说明

## 这个界面是做什么的

图书馆界面是系统的知识库维护台。

它的作用是把合规文档、平台政策、品牌资料、市场资料统一收进知识库，供后续脚本检查和合规链路检索使用。

你可以把它理解成：

- 左边负责上传资料
- 右边负责查看知识库运行状态
- 下方负责查看所有资料清单

## 这个界面能做什么

当前支持：

- 上传资料文件
- 给资料填写元信息
- 查看知识库状态
- 手动重建图书馆
- 刷新文档列表
- 查看所有资料的状态

## 左侧上传区是干嘛的

### 选择文件

当前支持上传：

- `.pdf`
- `.html`
- `.md`
- `.markdown`
- `.txt`

### 资料标题

不填时会默认使用文件名。

### 资料分类

包括：

- 平台政策
- 市场法律
- 品牌政策
- Campaign Brief
- 品牌历史
- 技术参考

### 优先级

用于知识库资料管理优先级。

### 市场 / 区域包 / 平台 / 语言

这些字段很重要，因为后续检索会依赖这些元信息。

它们会参与：

- 资料归档
- 检索过滤
- 合规范围匹配

### 原始来源链接

可选，用于保留来源地址。

### 备注

建议写这个资料是干嘛的，例如：

- 用于 TikTok 美国市场达人带货合规审查
- 用于某个品牌 campaign brief

### 上传资料

点击后，资料会先进入图书馆资料清单。

但这不等于已经完成向量入库。

## 为什么上传后还要“刷新 / 重建图书馆”

这是图书馆界面最关键的点。

当前系统不是“上传完立刻可检索”，而是两阶段流程：

1. 上传资料
2. 重建图书馆

原因是系统需要做：

- 原始文件归档
- 规范化处理
- 文档切片
- 向量索引重建

所以你上传完成后，常见状态会是：

- `待重建`

只有你执行重建后，资料才会真正进入最新索引。

## 右侧图书馆状态区怎么看

这里会显示：

- 当前状态
- 文档数
- 分块数
- 最近构建时间
- Embedding Backend
- 知识库目录
- 最近一次重建结果

这个区域主要用于判断：

- 知识库有没有正常工作
- 最近有没有成功重建
- 当前索引里有多少文档和 chunk

## 下方资料清单怎么看

每一条资料会显示：

- 标题
- source_id
- 文件来源类型
- 分类
- 优先级
- 平台 / 市场 / 区域 / 语言
- 当前状态
- 更新时间
- 来源链接
- 备注

最关键的是“状态”字段。

### 常见状态含义

`indexed`
- 表示已经进入当前索引

`pending_rebuild`
- 表示资料已上传，但还没进入最新索引
- 通常需要点一次“刷新 / 重建图书馆”

## 后端到底做了什么

图书馆模块的后端流程大致是：

1. 接收上传文件
2. 根据文件后缀分类处理
3. 写入 `raw/` 或直接写入 `processed/`
4. 更新 `source_catalog.json`
5. 文档列表里显示为待重建或已入库
6. 你点击重建后，系统规范化资料并重建知识运行时
7. 新索引进入 Qdrant

接口包括：

- `GET /library/health`
- `GET /library/documents`
- `POST /library/upload`
- `POST /library/rebuild`

后端实现：

## 数据流动

图书馆的数据流是：

1. 前端上传文件到 `/library/upload`
2. 后端把资料写入 `raw/` 或 `processed/`
3. 更新目录清单与元数据
4. 文档在列表中显示
5. 点击重建后，系统规范化文档并生成向量索引
6. Qdrant 更新
7. 脚本检查与合规链路后续可检索到这些资料

## 它和脚本检查的关系

图书馆和脚本检查关系最强。

因为：

- 脚本检查会去知识库里找证据
- 证据不够，审查质量就会下降

所以图书馆维护得越好，脚本检查越可靠。

## 最推荐的使用方式

如果你要新增一份政策文档，建议顺序是：

1. 上传文件
2. 确认资料清单里已出现
3. 看到状态为“待重建”是正常的
4. 点击“刷新 / 重建图书馆”
5. 再去脚本检查模块做验证

## 这个界面的定位总结

图书馆不是内容生产界面，而是系统的知识底座。

它决定了后续合规审查能不能“有依据地判断”。
