# 脚本生成界面说明

## 这个界面是做什么的

脚本生成界面是系统的内容生产台。

它的作用不是只输出一段文案，而是根据：

- 达人风格
- 主题
- 国家
- 平台
- 分发方式
- 品类
- 视频时长
- 输出语言

生成一份可直接用于拍摄的脚本草案，并自动附带合规审查和修订稿。

## 这个界面能做什么

当前支持：

- 选择达人
- 查看当前达人档案
- 输入主题
- 选择输出语言
- 选择国家
- 选择平台
- 选择分发方式
- 选择品类
- 选择视频时长
- 输入品牌 ID
- 调节温度 / Creativity
- 选择是否保存脚本记录
- 生成脚本

生成完成后会显示：

- 模型信息
- 生成稿
- 修订稿
- 合规报告

## 左侧控制区分别是什么意思

### 达人选择

这里选的是脚本风格来源。

系统会读取该达人对应的：

- 名称
- 平台
- 备注描述

其中“备注描述”会成为达人风格提示词的重要来源。

### 达人档案

这里是只读展示区。

它的作用是提醒你：

- 当前你在用哪个达人
- 当前达人有没有写好备注描述

如果这里内容很空，生成出来的脚本通常会更通用、不够像真人达人。

### 主题

这是脚本生成最核心的输入。

你可以理解为：

- 这条视频讲什么
- 这条视频的选题是什么

建议写得具体一些，例如：

- 为什么年轻人不爱换手机了
- AI 眼镜到底是噱头还是刚需
- 预算不高怎么把旧手机拍出大片感

### 输出语言

这里决定脚本生成的语言版本。

你可以勾选多个语言，系统会按顺序输出多语言版本。

### 国家

决定脚本面向哪个市场。

这个会影响：

- 表达方式
- 市场语境
- 合规判断范围

### 平台

决定脚本更偏哪种内容风格。

例如：

- TikTok 更强调前 3 秒钩子和快节奏
- YouTube Shorts 会略偏可读性和 retention

### 分发方式

决定内容场景。

可选：

- `Organic Post`
- `Branded Content`
- `Paid Ads`

这个字段会直接影响：

- 脚本生成方向
- 合规要求

### 品类

告诉系统你做的是哪种产品或内容。

这个会影响：

- 用词风格
- 热点参考方向
- 合规风险类型

### 视频时长

决定脚本节奏和分镜长度。

当前可选：

- `15s (Flash)`
- `30s (Standard)`
- `60s (Immersive)`
- `3min (Deep Dive)`

### 品牌 ID

这是给系统保留的品牌上下文字段。

当前它已经会进入后端工作流，但是否触发更深的品牌逻辑，取决于后续品牌知识库扩展。

### 是否保存脚本记录

这个选项非常实用。

含义是：

- `否，仅试运行`：只看结果，不写入历史脚本表
- `是，写入脚本记录`：把这次生成结果保存进 `scripts`

### 温度 / Creativity

它控制创意发散程度。

简单理解：

- 数值低：更稳、更保守
- 数值高：更活、更跳、更容易出现大胆表达

## 右侧输出区怎么看

### 模型信息

这里会显示这次使用的是哪个模型提供商和模型名。

如果主模型失败，系统有可能回退到备用模型。

### 生成稿

这是脚本生成器最先产出的版本。

它是拍摄脚本原稿。

### 修订稿

这是经过合规审查后，系统给出的更安全版本。

如果原稿命中了风险，这里通常比“生成稿”更适合最终交付。

### 合规报告

这里会展示：

- 状态
- 风险等级
- 问题数
- 风险摘要
- 每条问题的原因和修改建议

## 后端到底做了什么

这不是单次 LLM 问答，而是一条工作流。

当前生成链路大致是：

1. 读取达人资料
2. 读取热点趋势
3. 生成原始脚本
4. 解析审查范围
5. 从知识库检索证据
6. 运行规则引擎
7. 生成合规报告
8. 输出修订稿
9. 按需写入 `scripts`

接口位置：

- `POST /scripts/generate`

服务层：

- [scripts.py](/Users/bailumac/Developer/my-grad-proj/backend/services/scripts.py)

工作流入口：

- [workflow.py](/Users/bailumac/Developer/my-grad-proj/core/workflow.py)

## 数据流动

脚本生成的数据流是：

1. 前端表单发到 `/scripts/generate`
2. 后端组装工作流状态
3. 工作流调用达人风格、趋势、写作、合规、修订链路
4. 返回 `final_script`、`approved_script`、`compliance_report`
5. 如果勾选保存，则写入 PostgreSQL 的 `scripts`

## 这个界面的关键特点

它不是“只出一稿”。

它其实一次性产出的是：

- 原始脚本
- 合规判断
- 风险列表
- 修订脚本

所以正确的使用方式不是只看“生成稿”，而是：

优先看“修订稿 + 合规报告”。

## 使用建议

如果你想要结果更稳定：

- 达人备注要写清楚
- 主题要具体
- 国家 / 平台 / 分发方式要对应真实场景
- 温度不要拉太高

如果你想要结果更有创意：

- 主题可以写得更像选题标题
- 温度可以适当提高
- 输出语言不要一次勾太多，先把主语言跑稳

## 这个界面的定位总结

脚本生成界面是系统的内容生产核心。

它负责把达人风格、市场背景、热点信息和合规要求，整合成一份可执行脚本。
